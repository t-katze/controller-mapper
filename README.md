# Controller Mapper

フライトスティック、スロットル、ラダーペダルなどの入力を読み取り、補正・変換して仮想コントローラへ出力するWindows向けGUIアプリです。

このREADMEは、Releaseとして配布している `dist\controller-mapper-v0.1.0-win-x64.zip` を使う人向けです。ソースコードから起動・開発・ビルドする手順は [docs/source.md](docs/source.md) を参照してください。

## できること

- 物理コントローラの軸、ボタン、Hat/D-pad入力を読み取る
- デッドゾーン、カーブ、反転、スムージング、デバウンスをかける
- 軸をボタンに変換する
- 軸の正負方向を2つのボタンに分ける
- ボタンを軸に変換する
- 2ボタンを1つの軸操作として扱う
- ボタンのON/OFFを別々のvJoyボタンへ分ける
- プロファイルを読み込み、GUI上でマッピングを追加・編集・保存する
- `nav` / `aa` / `ag` などのモード別マッピングを切り替える
- 入力状態、フィルタ後の値、仮想デバイスへの出力状態をリアルタイム表示する

主対象はDCS WorldやMicrosoft Flight Simulatorなどのシミュレータです。

## 必要なもの

- Windows 10/11
- Release zip: `controller-mapper-v0.1.0-win-x64.zip`
- vJoyドライバ
- 使用するジョイスティック、HOTAS、ペダルなど

Pythonは不要です。Release zipには実行に必要なPythonランタイムとライブラリが同梱されています。

vJoy出力を使わず、入力の確認やプロファイル編集だけを行う場合はvJoyなしでも起動できます。その場合、出力は `Null (テストモード)` になります。

## vJoyの準備

1. vJoyをインストールします。
2. Windowsを再起動します。
3. vJoy Configなどで `Device 1` を有効にします。
4. 使いたい軸とボタン数を確保します。

同梱の `DCS.yaml` は `vJoy Device 1` へ出力する設定です。

vJoyのインストーラは、進捗が100%になったあとに完了画面へ進まず、止まったように見えることがあります。この状態でキャンセルしても、ドライバ自体は正常に入っている場合があります。キャンセル後にWindowsを再起動し、vJoy ConfigやWindowsのゲームコントローラ設定でvJoy Deviceが見えるか確認してください。見えていれば、そのままController Mapperで使用できます。

vJoyが初期化できない場合、アプリは警告を表示して `NullBackend (テストモード)` にフォールバックします。この状態ではGUI上で変換結果は見られますが、ゲームへvJoy入力は送られません。

## インストールと起動

1. Releaseから `controller-mapper-v0.1.0-win-x64.zip` をダウンロードします。
2. zipを任意のフォルダへ展開します。
3. 展開したフォルダ内の `controller-mapper\controller-mapper.exe` を起動します。

フォルダ構成は概ね次の形です。

```text
controller-mapper/
  controller-mapper.exe
  _internal/
    profiles/
      DCS.yaml
    ...
```

`_internal` フォルダには実行に必要なDLL、Pythonランタイム、同梱プロファイルが入っています。削除したり移動したりせず、`controller-mapper.exe` と同じフォルダ構成のまま使ってください。

## 最初の使い方

1. コントローラとvJoyを接続した状態で `controller-mapper.exe` を起動します。
2. `Devices` タブで物理デバイスが検出されていることを確認します。
3. `Dashboard` タブの `プロファイル読み込み` を押します。
4. 展開先の `_internal\profiles\DCS.yaml`、または自分で作った `.yaml` プロファイルを選びます。
5. `Dashboard` の出力表示が `vJoy Device 1 (接続済み)` になっていることを確認します。
6. `開始` を押します。
7. `Monitor` または `Output` タブで、入力や出力が動いていることを確認します。
8. DCSなどゲーム側で `vJoy Device` に操作を割り当てます。

停止するときは `Dashboard` の `停止` を押します。アプリを閉じると変換パイプラインも停止します。

## 同梱プロファイル

同梱プロファイルは `DCS_F16_X56` です。

場所:

```text
controller-mapper\_internal\profiles\DCS.yaml
```

主な設定:

- 出力: `vJoy Device 1`
- 更新周期: 500 Hz
- モード: `nav`, `aa`, `ag`
- 例: エアブレーキスイッチのON/OFFを別々のvJoyボタンへ分割
- 例: ホイールブレーキ軸のマイナス方向をボタン化
- 例: サブスティックのX/Y軸を正負2方向のボタンに変換

このプロファイルは環境により入力デバイスIDが合わない場合があります。`Devices` タブで実際の `pygame_0` などのIDを確認し、`Mapping` タブで入力デバイスやインデックスを調整してください。

## 画面ごとの使い方

### Dashboard

現在の状態を確認し、プロファイル読み込み、開始、停止、起動設定を行う画面です。

- `プロファイル読み込み`: YAMLプロファイルを読み込みます。
- `開始`: 入力読み取り、変換、出力を開始します。
- `停止`: 変換を停止します。
- `デフォルトプロファイル`: 起動時に自動で読み込むプロファイルを指定します。
- `現在のプロファイルを設定`: 今読み込んでいるプロファイルをデフォルトにします。
- `起動時に自動開始する`: デフォルトプロファイル読み込み後に自動で開始します。
- `設定を保存`: 起動設定を保存します。

起動設定は次のファイルに保存されます。

```text
%USERPROFILE%\.controller_mapper\settings.yaml
```

### Devices

接続されている入力デバイスの一覧を表示します。

確認できる内容:

- デバイスID
- デバイス名
- 軸数
- ボタン数
- Hat数
- バックエンド
- GUID

コントローラを接続し直した場合は `再スキャン` を押してください。動作中に再スキャンすると、一度停止してからデバイスを更新し、必要に応じて動作を再開します。

### Monitor

入力と変換結果をリアルタイムで確認する画面です。

- `Raw`: 物理デバイスから読んだ生の値
- `Out`: フィルタ後の値
- ボタン表示: 押されているボタンがON表示になります
- Hat表示: Hat/D-padの方向を `(x, y)` で表示します
- `Output`: 仮想デバイスへ送る軸・ボタン状態を表示します

マッピングがうまく動かないときは、まずここで物理入力が正しく読めているか確認してください。

### Calibration

軸入力の補正値を調整します。

設定できる項目:

- デッドゾーン
- エンドデッドゾーン
- カーブ指数
- スムージング
- 反転

`適用` を押すと、現在読み込んでいるプロファイル内の `axis -> axis` ルールへ値が反映されます。主操縦軸にスムージングを強くかけすぎると操作遅れが出ます。ダイヤルやスライダーは比較的強めにしても問題が出にくいです。

### Mapping

プロファイル内のマッピングルールを一覧・追加・編集・削除・保存する画面です。

基本操作:

- `追加`: 新しいルールを作ります。
- `編集`: 選択中のルールを編集します。行のダブルクリックでも開けます。
- `削除`: 選択中のルールを削除します。
- `保存`: 読み込んだプロファイルへ上書き保存します。
- `別名保存`: 別ファイルとして保存します。

ルール編集では、入力、変換、出力、フィルタを設定します。

入力タイプ:

- `axis`: 軸入力
- `button`: ボタン入力
- `button_pair`: 2つのボタン入力
- `hat`: Hat/D-pad入力

変換タイプ:

- `パススルー`: 入力をそのまま出力
- `軸→ボタン`: 軸値が閾値を超えたらボタンON
- `軸(-方向)→ボタン`: 軸のマイナス方向でボタンON
- `軸→2ボタン (正負)`: 軸のマイナス方向とプラス方向を別ボタンへ出力
- `ボタン→軸`: ボタンのON/OFFを軸値へ変換
- `2ボタン→軸`: 2つのボタンで1つの軸を操作
- `ボタン分割`: ボタンONとOFFを別々のボタンとして出力

一部の入力インデックスには `検出` ボタンがあります。押したあとに実機のボタンや軸を操作すると、その入力番号を拾えます。

### Modes

プロファイルに定義されたモードを切り替えます。

同梱の `DCS.yaml` では次のモードがあります。

- `nav`
- `aa`
- `ag`

各ルールは `*` なら全モード共通、特定のモード名ならそのモード中だけ有効になります。

### Output

仮想デバイスへ送っている出力状態を表示します。

- 出力バックエンド
- 出力軸
- 出力ボタン

ゲーム側に入力が届かない場合でも、この画面で出力が動いていれば、Controller Mapper内の変換までは動作しています。その場合はvJoy接続、ゲーム側の割り当て、物理デバイスとの二重入力を確認してください。

### Logs

起動、プロファイル読み込み、バックエンド初期化、エラーなどのログを表示します。

エラーが起きた場合は、まず `Logs` タブの内容を確認してください。

## プロファイルの基本

プロファイルはYAMLファイルです。大きく次の設定を持ちます。

```yaml
profile:
  name: My_Profile
  version: 1

output:
  type: vjoy
  device_id: 1

global:
  update_rate_hz: 500
  gui_rate_hz: 30

modes:
  default: nav
  definitions:
    - nav
    - aa
    - ag

rules:
  - name: example
    mode: "*"
    input:
      device: pygame_0
      type: button
      index: 0
    transform:
      type: button_split
      off_button: 1
    output:
      type: button
      index: 0
```

よく編集する場所は `rules` です。GUIの `Mapping` タブから編集して保存できます。

## ゲーム側の設定

1. Controller Mapperでプロファイルを読み込み、`開始` します。
2. ゲーム側のコントローラ設定で `vJoy Device` を選びます。
3. Controller Mapperの出力ボタンや軸を動かしながら、ゲーム側へ割り当てます。
4. 物理デバイスとvJoyの両方が同じ操作に割り当たっていないか確認します。

ゲームが物理デバイスとvJoyの両方を拾うと、二重入力になります。必要に応じてゲーム側で物理デバイスの割り当てを消すか、HidHideなどで物理デバイスをゲームから隠してください。

## トラブルシュート

### 起動しない

- zipを完全に展開してから起動してください。
- `controller-mapper.exe` だけを別フォルダへ移動しないでください。
- セキュリティソフトに隔離されていないか確認してください。

### デバイスが表示されない

- コントローラを接続し直して `Devices` の `再スキャン` を押してください。
- 他のアプリがデバイスを占有していないか確認してください。
- アプリを起動し直してください。

### vJoyに接続できない

- vJoyがインストールされているか確認してください。
- `Device 1` が有効か確認してください。
- Windowsを再起動してください。
- プロファイルの `output.device_id` とvJoy側のDevice番号を合わせてください。
- vJoyインストーラが100%で止まったように見えた場合でも、キャンセル後にインストール済みになっていることがあります。再起動後、vJoy ConfigまたはWindowsのゲームコントローラ設定でvJoy Deviceが表示されるか確認してください。

### ゲームに入力が届かない

- `Output` タブで出力が動いているか確認してください。
- 出力が動いていない場合は、`Monitor` タブで物理入力が読めているか確認してください。
- ゲーム側で `vJoy Device` に割り当ててください。
- 物理デバイス側の割り当てが残っていて二重入力になっていないか確認してください。

### マッピングが反応しない

- `Devices` タブのデバイスIDと、ルールの入力デバイスが一致しているか確認してください。
- 入力インデックスが正しいか確認してください。
- ルールの `mode` が現在のモードと一致しているか確認してください。
- 閾値が高すぎないか確認してください。

## 注意事項

- vJoyはWindows向けの仮想ジョイスティックドライバです。ドライバ導入後は再起動が必要になることがあります。
- 対戦ゲームやアンチチートが有効なゲームでは、仮想入力や入力変換ツールが検出対象になる場合があります。
- このソフトはシミュレータ用途を主対象としています。
- Release zip内の `_internal` はアプリの実行に必要です。手動で整理しないでください。
